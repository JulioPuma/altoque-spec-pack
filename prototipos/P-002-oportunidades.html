Comportamiento a validar

  • Cada oferta vigente tiene su propio botón «Simular» con su identificador: el cliente elige explícitamente con cuál simular.
  • Las ofertas vencidas se listan solo como referencia, sin acción. El vencimiento llega del sistema; la pantalla no lo calcula.
  • «Iniciar solicitud regular» es una acción explícita y no anula las ofertas preferenciales vigentes. Si ya existe una solicitud activa, se muestra esa en lugar de crear otra.
  • «Actualizar» es solo lectura. Si falla, se conserva la última lectura confirmada con su hora y se avisa que no se pudo actualizar.
  • La primera visualización de cada oferta se registra una sola vez (OPPORTUNITY_VIEWED), aunque la lista se recargue.
  • Límite, consumo, reservas y disponible son importes informados por el sistema. El saldo se vuelve a validar al contratar.

Reglas aplicadas

  • RN-001 Sesión autenticada válida para consultar oportunidades.
  • RN-002 / RN-237 / RN-243 Solo recursos propios; nunca se revelan ofertas ajenas.
  • RN-003 / RN-168 Oferta vencida, reemplazada o contratada no admite nuevas simulaciones.
  • RN-169 / RN-170 Selección explícita del ofertaId; cada oferta es una oportunidad independiente.
  • RN-171 / RN-172 El flujo regular nunca se inicia solo y no invalida ofertas vigentes.
  • RN-173 No se crea una segunda solicitud regular activa.
  • RN-086 Ambos recorridos comparten la línea única del cliente.
  • RN-026 / RN-261 Visualización contada una vez por cliente y oferta.
  • RN-006 El frontend no calcula importes. RN-028 Operable por teclado.
