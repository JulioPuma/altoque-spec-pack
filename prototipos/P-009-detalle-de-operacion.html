Detalle de operación

La contratación y el desembolso simulado tienen estados independientes.

Entorno de evaluación con datos sintéticos. No se mueve dinero real.

Comportamiento a validar

  • Contratación y desembolso tienen secciones, estados y versiones separados; el resumen solo los describe con texto.
  • «Actualizar estado» solo consulta. Si el backend avanzó entre lecturas (por ejemplo, Procesando → Exitoso), se muestra el cambio; la consulta no lo provoca.
  • En «Consultando estado», al actualizar, el core responde operación no encontrada: el desembolso vuelve a pendiente, no a fallido.
  • Pendiente o en revisión: se explica que no se debe iniciar otra contratación y que se recupera la misma operación, sin crear otra.
  • Error de red: se conserva la última lectura confirmada, marcada como no actualizada.
  • Un ID inexistente y uno de otro cliente muestran el mismo mensaje. Prueba ?intento=CTR-ATT-9999.
  • La contradicción tardía abre un expediente separado; el resultado terminal no cambia.
  • Los importes y condiciones son valores devueltos por el backend; la pantalla no los calcula.

Reglas aplicadas

  • RN-032 / RN-153 Un terminal confirmado no se modifica.
  • RN-152 / RN-236 Evidencia contradictoria: expediente de conflicto separado, sin tocar el terminal.
  • RN-021 / RN-022 / RN-052 / RN-148 Timeout u «operación no encontrada» mantienen el desembolso pendiente.
  • RN-023 / RN-024 La recuperación consulta la operación original; no crea otra.
  • RN-048 / RN-182 Pendiente o en revisión bloquea otro intento para la oportunidad y conserva la reserva.
  • RN-185 / RN-072 No se infiere un resultado por el tiempo ni por una lectura no disponible.
  • RN-031 / RN-180 Solo «No completada · recuperable» ofrece reintento, con el mismo intento.
  • RN-091 / RN-178 / RN-179 Rechazo o fallo definitivo liberan la reserva una vez.
  • RN-053 / RN-147 «Fallido» solo con evidencia de que no se ejecutó.
  • RN-122 / RN-243 Sin revelar operaciones ajenas.
